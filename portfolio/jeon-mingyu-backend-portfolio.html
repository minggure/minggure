DESIGN FOR FAILURE

Redis 상태가 불확실하면
발급부터 멈춥니다

정확한 재고를 모른 채 MySQL로 우회하면 Redis와 MySQL이 각각 재고를 판단합니다. 연결 장애나 필수 키 누락을 감지하면 HTTP 503으로 요청을 끝내고, MySQL의 실제 쿠폰으로 Redis를 다시 만듭니다.

UNAVAILABLE · 새 발급 차단

연결 장애나 필수 키 누락을 감지하면 새 요청을 HTTP 503으로 종료합니다.

RECOVERING · MySQL 검사

실제 쿠폰 수와 당첨 사용자 집합을 읽어 성공 결과가 맞는지 확인합니다.

Redis 데이터 재구축

재고, 당첨자, 회차 컨텍스트를 Lua로 함께 교체합니다.

재구축 결과가 기대값과 같을 때만 발급을 다시 엽니다.

AFTER · 발급과 집계 분리

  • 발급 transaction은 실제 쿠폰만 저장
  • 5초마다 한 번 GROUP BY
  • 전용 인덱스로 집계 범위 축소
  • MySQL named lock으로 중복 실행 차단

DB에 들어오기 전에 끝낸 요청

중복 신청과 품절 요청은 Redis에서 판정해 MySQL에 접근하지 않습니다. 발급 transaction에는 사용자 쿠폰 저장만 남기고, 조회용 성공 수량은 최대 5초의 차이를 허용했습니다.

SECOND PROJECT · DAENGGO-BE

게시글·댓글 기능을 실제 인증 흐름에 연결했습니다

Daenggo는 반려견 동반 장소 검색, 산책 기록, 커뮤니티를 제공하는 팀 프로젝트입니다. 커뮤니티 백엔드와 팀의 로컬 실행 환경을 맡았습니다.

게시글과 댓글 API

게시글·댓글의 등록, 조회, 수정, 삭제 흐름과 DTO·Entity·Repository 구조를 구현했습니다.

이미지와 조회수

게시글 이미지 등록·편집을 연결하고 조회 요청에서 조회수를 갱신했습니다.

작성자 권한 검증

로그인 사용자와 작성자를 비교해 작성자만 게시글과 댓글을 수정·삭제하도록 막았습니다.

실행 환경 통합

Docker Compose와 Nginx로 프론트엔드, 백엔드, MySQL의 실행 절차를 맞췄습니다.
