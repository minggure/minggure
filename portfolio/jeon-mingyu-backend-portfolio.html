JEON MINGYU02 · RECOVERY & PERFORMANCE
DESIGN FOR FAILURE

Redis가 비어 있어도 초과 발급하지 않도록

정확한 재고를 알 수 없을 때 MySQL로 우회 발급하면 두 개의 동시성 경로가 생깁니다. 발급을 중단하고 신뢰 가능한 원본에서 복구하는 Fail Closed 정책을 선택했습니다.

UNAVAILABLE · 발급 차단

연결 장애나 필수 키 누락을 감지하면 새 요청을 HTTP 503으로 종료합니다.

RECOVERING · 정합성 검증

성공 요청, 실제 쿠폰 수와 사용자 집합이 일치하는지 먼저 확인합니다.

재고·당첨자·컨텍스트 재구축

MySQL의 실제 쿠폰을 기준으로 Redis 데이터를 Lua로 함께 교체합니다.

READY · 결과 재검증 후 재개

기대값과 같을 때만 발급을 재개하고 불일치 시 자동 복구를 중단합니다.
